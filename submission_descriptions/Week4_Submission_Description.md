# YuvaIntern Portal Description — Week4

**Word count: 226**

This Week 4 submission compares fraud-classification approaches on the established training and validation partitions. The original test dataset is not used for fitting, tuning, validation, or reported performance. The target, TransactionID, and TransactionDT are not included as model features. A simple dummy classifier provides an imbalance-aware baseline, followed by weighted logistic regression and a weighted HistGradientBoostingClassifier using a compact set of numeric and categorical inputs. Preprocessing is fitted using the training-fit partition only, then applied to validation. The workflow reports precision, recall, F1, ROC-AUC and average precision (PR-AUC), plus confusion-matrix counts and evaluation charts.

The dummy baseline reached about 96.5% accuracy but had zero fraud precision and recall, illustrating why accuracy is misleading when only about 3.5% of transactions are fraudulent. Logistic regression achieved validation recall 0.6366, F1 0.1750, ROC-AUC 0.7886 and average precision 0.2748. HistGradientBoosting achieved recall 0.7239, F1 0.2341, ROC-AUC 0.8569 and average precision 0.4218; at the selected threshold it produced 2,992 true positives, 18,432 false positives, 1,141 false negatives and 95,543 true negatives. These metrics represent one validation split and threshold, not a deployment guarantee. The report explains the cost trade-off between false alarms and missed fraud, discusses the limits of overfit assessment, and outlines improvements such as threshold calibration and broader validation. Reproducible code, metrics, verification evidence and charts are included; model binaries and validation-prediction files are excluded from this public-ready package.
